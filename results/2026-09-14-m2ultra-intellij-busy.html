Congo Kotlin Bench

CongoCC's generated Kotlin parser against the Kotlin compiler's own parser, on 8,013 real-world .kt files. Parsing plus a full depth-first walk of the tree, the compiler's parser (ast) is about 4× faster and allocates a ninth of the memory.

Not a clean run. IntelliJ was using a full core throughout, so fork medians spread by up to 18% at 16 threads. Read the absolute throughput as approximate. The ratio held on every fork: paired by fork, ast stayed 3.5–4.6× ahead of congo.

The four parsers

Every parser gets the same in-memory text, builds its tree, and the tree is walked depth-first, into function bodies and lambdas too.

congo

CongoCC, grammar from congo-grammars/kotlin. new KotlinParser(name, text).KotlinFile(), walked with Node.get(i).

ast headline

The compiler's parser (KotlinParsing + JFlex lexer via PsiBuilder) with the PSI features stripped: no PsiFile, no wrappers, no lazy blocks, no KDoc.

lighttree reference

KotlinLightParser.buildLightTree, exactly what kotlinc (K2) runs. A flyweight tree with no node objects.

psi reference

KtPsiFactory.createFile, the full PSI tree that the IDE and the Analysis API get.

Where congo spends its time

From a single-threaded JFR profile of the congo run.

  • 24%of CPU

    In the TOKEN_HOOK of Kotlin.ccc: every newline token calls canIgnoreNewlines(), which walks the whole parser call stack comparing production names. The Kotlin compiler answers the same question in constant time, with a stack of flags in SemanticWhitespaceAwarePsiBuilder.

  • 40%of allocation

    Keeping that call stack costs a NonTerminalCall per production entry.

  • 14%of CPU

    BitSet.nextSetBit in TokenSource.nextCachedToken.

  • 7%of CPU

    Soft-keyword String.contentEquals in typeMatches / hasMatch.

Setup

Machine
Apple M2 Ultra, 16 performance + 8 efficiency cores. IntelliJ busy on one core.
JVM
OpenJDK 21.0.12.1, -Xms8g -Xmx8g -XX:+AlwaysPreTouch, default G1
Versions
Kotlin compiler 2.4.0 · congo-grammars f1443fe
Corpus
8,013 .kt files, 35.2 MB, from 11 projects at pinned revisions (ktor, Exposed, detekt, kotlinx.coroutines and others). Only files both parsers accept: CongoCC rejects 56 files that Kotlin accepts, 33 of them for newer syntax such as context parameters.
Protocol
Each (parser, threads) pair runs in its own JVM, in 3 interleaved forks. 1 thread: 5 warm-up + 10 measured passes. 16 and 24 threads: 10 + 20. A pass parses and walks the whole corpus. Files are handed out largest first from a shared counter.
Parity
Node counts must be identical on every pass. The three Kotlin walks agree with each other, and the non-whitespace source text reachable from both trees is compared per file.
